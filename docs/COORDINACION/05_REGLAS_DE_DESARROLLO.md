# Reglas de desarrollo

1. Leer coordinación, main, PR, ramas, Issues y código antes de iniciar.
2. Identificar dueño y evitar duplicaciones; avisar antes de modificar archivos compartidos.
3. Rama desde main reciente, un PR coherente, detallar cambios, tests, dependencias y riesgos.
4. Migraciones únicas y validadas. Seguridad tenant y RBAC comprobados en backend.
5. Estados: PROPUESTO → ASIGNADO → EN DESARROLLO → EN PRUEBAS → PR ABIERTO → INTEGRADO → DESPLEGADO → VERIFICADO; BLOQUEADO o CANCELADO según evidencia.
6. Prohibidos merge y despliegue sin autorización expresa y pruebas apropiadas.
